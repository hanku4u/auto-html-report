## 1. Purpose and scope

`auto_inform` is a Python library that assembles **reports** — single, self-contained HTML files
containing one table with three columns: **Item**, **Data**, **Check**.

Each row of that table is contributed by a **Block**: a small, self-contained class that knows how
to gather one discrete piece of information (a maintenance history from an API, a failing wafer
map, a trend chart) and how to render it as an HTML fragment. The framework guarantees:

- blocks run **concurrently**, each with its own timeout and retry budget;
- a block that fails does **not** take the report down — the failure is rendered into that block's
  cell;
- row order is **deterministic** (the order blocks were supplied);
- the finished document is **self-contained** — inline CSS, images embedded as data URIs, no
  external requests, no JavaScript dependency.

The library also supports a two-phase workflow for report families that scale with discovered
data:

1. **Discovery** — a scheduled job polls APIs for *events* and persists them to an event store.
2. **Processing** — a second (independently scheduled) job reads pending events, selects the report
   definition registered for each event *type*, builds the report, and writes it out.

The two phases are deliberately decoupled: they share only the event store, so either can fail,
be re-run, be throttled, or be scheduled on a different cadence without affecting the other.

### 1.1 Non-goals for v1

| Not doing | Why |
| --- | --- |
| Web service / REST API | Reports are generated by scheduled jobs, not served on request. |
| Scheduler / cron implementation | The host CI system owns scheduling. |
| Command-line interface | Deliberate: library-only public surface (see ADR-0001). |
| Interactive JS charts | matplotlib → static PNG data URI (ADR-0009). |
| PDF or Excel export | HTML only in v1. |
| Publishing to PyPI | Internal tool, installed from git (ADR-0015). |
| External plugin packages | Blocks are added to this package directly (ADR-0003). |
| Multi-report-per-file, or a block expanding to multiple rows | One block = one row in v1 (ADR-0011). |
| End-user templating language | Report definitions are Python (ADR-0016). |

## 2. Glossary

Precision matters here, because "report" is overloaded in ordinary speech.

| Term | Meaning |
| --- | --- |
| **Block** | A class implementing `Block`. Produces exactly one table row. Splits into a `collect()` phase (I/O) and a `render()` phase (pure). |
| **ReportDefinition** | Immutable description of one report: a title plus an ordered sequence of *instantiated* blocks. Pure data; no I/O. |
| **Report** | The assembled result: ordered `ReportRow`s, the run id, and the generation timestamp. Still framework data — not yet HTML. |
| **ReportRow** | One row: `item` (Item column), `html` (Data column fragment), `check` (empty in v1), and the `BlockOutcome`. |
| **Event** | An immutable value object discovered from an external source: `event_type`, `event_id`, `payload`, `discovered_at`, `source`. |
| **EventStore** | Port that persists events and tracks their lifecycle (`NEW` → `PROCESSED` / `FAILED`). Default: SQLite. Optional: PostgreSQL. |
| **Discoverer** | A class implementing `Discoverer` that produces `Event`s for one `event_type`. |
| **ReportFactory** | Callable `(event, context) -> ReportDefinition`. Registered per `event_type`; answers "which blocks, with which parameters, for *this* event?" |
| **Generation** | The act of turning a `ReportDefinition` into assembled `Report` rows (`generate_report`). |
| **Renderer** | Pure function turning a `Report` into an HTML string. |

## 3. Architectural overview

Dependencies point **inwards**. The domain knows nothing about SQLite, S3, Jinja2 or matplotlib;
those live behind ports and are wired at the edge. This is what makes blocks testable without a
network and the framework testable without a bucket.

```
                            ┌──────────────────────────────────────┐
   client code (CI jobs) →  │  public API:  auto_inform/__init__.py │
                            └──────────────────────────────────────┘
                                            │
        ┌───────────────────────────────────┼─────────────────────────────────┐
        ▼                                   ▼                                 ▼
┌────────────────┐              ┌──────────────────────┐          ┌───────────────────┐
│  application   │              │   domain (pure)      │          │  infrastructure   │
│                │  depends on  │                      │  implements ┌───────────────┐ │
│ generate_report│ ───────────► │ Block / Report...    │ ◄─────────── │ SqliteStore   │ │
│ run_discovery  │              │ Event / ExitCode     │  ports       │ PostgresStore │ │
│ run_processing │ ───────────► │ errors               │              │ LocalWriter   │ │
│ collect_blocks │              └──────────────────────┘              │ S3Writer      │ │
└────────────────┘                          ▲                        │ HttpClient    │ │
        │                                   │                        │ settings      │ │
        ▼                        ┌──────────────────────┐            └───────────────┘ │
```

### 3.1 The two pipelines

```
DISCOVERY JOB  (e.g. every 15 min via CI scheduler)
  Discoverer(s) ──discover()──► [Event, Event, ...] ──store.save()──►  EventStore
       (own ReportContext: settings, http, logger, clock)              (NEW rows)

PROCESSING JOB  (e.g. every hour via CI scheduler)
  EventStore.pending(event_type) ──► Event
        │
        ├─ get_report_factory(event_type)(event, context) ──► ReportDefinition
        │        (event-specific parameters are bound here, explicitly, by the factory)
        │
        ├─ generate_report(definition, context)  ── concurrent per-block collect + render
        │        └─► Report (ordered rows, per-block outcomes)
        │
        ├─ render_report(report) ──► HTML string
        │
        ├─ OutputWriter.write(...) ──► local directory or S3
        │
        └─ EventStore.mark_processed(event_id, uri)  |  mark_failed(event_id, reason)
```

**Rules enforced by review (and later by an import-linter in CI):**

1. `domain/` imports nothing from `application/`, `infrastructure/` or `rendering/`.
2. `application/` imports `domain/` and `ports` only — never `infrastructure/` or `rendering/`.
3. Concrete stores/writers are injected by the caller (or by a small factory that reads `Settings`).
4. Blocks live in `blocks/` and import from `domain/` and `rendering/helpers` — never from
   `infrastructure/`. They receive everything they need through `ReportContext` and their own
   constructor parameters.

### 4.2 The Block contract

```python
# auto_inform/domain/block.py
from __future__ import annotations

from abc import ABC, abstractmethod
from typing import ClassVar, Generic, TypeVar

DataT = TypeVar("DataT")


class Block(ABC, Generic[DataT]):
    """One row of a report.

    Subclasses split the work in two so that rendering stays trivially testable:
      collect() -> I/O, allowed to be slow and to fail
      render()  -> pure transformation, no I/O, no clock, no randomness
    """

    #: Default text for the "Item" column. Overridable per instance via ``name=``.
    display_name: ClassVar[str] = ""

    #: Per-block overrides; ``None`` means "use the framework default from Settings".
    timeout_seconds: ClassVar[float | None] = None
    max_retries: ClassVar[int | None] = None

    def __init__(self, *, name: str | None = None) -> None:
        resolved = name or self.display_name
        if not resolved:
            raise ValueError(
                f"{type(self).__name__} must set display_name or pass name=..."
            )
        self._name = resolved

    @property
    def name(self) -> str:
        """Text shown in the Item column. Must be unique within a report."""
        return self._name

    @abstractmethod
    def collect(self, context: ReportContext) -> DataT:
        """Gather this block's data. Runs in a worker thread; I/O permitted."""

    @abstractmethod
    def render(self, data: DataT, context: RenderContext) -> str:
        """Return the inner HTML for this block's Data cell. Must be pure."""
```

Design notes for the implementer:

- **`name` is a property, not a bare ClassVar**, because the same block type is frequently
  instantiated several times in one report with different parameters (`Maintenance — T-104` vs
  `Maintenance — T-112`). Static typing via `display_name` keeps the simple case one line.
- **`render()` receives the `DataT` produced by its own `collect()`.** The framework treats that
  value as opaque (`Any`); it is typed end-to-end only for the block author's benefit. The
  framework never inspects it, serialises it, or passes it between blocks. **Blocks do not talk to
  each other** — if two blocks need the same data, they fetch it themselves, or a `ReportFactory`
  fetches it once and injects it as a constructor argument (see §4.6).
- **`render()` must not raise.** The framework wraps it defensively and substitutes an error cell
  if it does, but a render bug is a code defect, not a data condition, and it should be caught in
  tests.
- **`collect()` must be safe to call from a non-main thread.** No `matplotlib` figure creation in
  `collect()` — figures belong in `render()` where the module lock serialises them (§5.4).

### 4.3 A worked block

```python
# auto_inform/blocks/maintenance_history.py
from __future__ import annotations

from dataclasses import dataclass

from auto_inform import Block, ReportContext, RenderContext, html_table
from auto_inform.domain.block import TransientBlockError


@dataclass(frozen=True, slots=True)
class MaintenanceRecord:
    performed_at: str
    engineer: str
    summary: str


class MaintenanceHistoryBlock(Block[list[MaintenanceRecord]]):
    """Recent maintenance events for one tool."""

    display_name = "Maintenance history"
    timeout_seconds = 30.0

    def __init__(self, *, tool_id: str, days: int = 30, name: str | None = None) -> None:
        super().__init__(name=name or f"Maintenance history — {tool_id}")
        self._tool_id = tool_id
        self._days = days

    def collect(self, context: ReportContext) -> list[MaintenanceRecord]:
        # The HTTP client is injected; blocks never build their own clients (ADR-0017).
        # STUB in v1: StubHttpClient returns canned fixtures. See §7.2.
        payload = context.http.get_json(
            f"/maintenance/{self._tool_id}",
            params={"days": self._days},
            timeout=context.settings.block_timeout_seconds,
        )
        if payload.get("status") == "degraded":
            raise TransientBlockError("maintenance service degraded; retry later")
        return [MaintenanceRecord(**row) for row in payload["records"]]

    def render(self, data: list[MaintenanceRecord], context: RenderContext) -> str:
        if not data:
            return '<p class="ai-empty">No maintenance recorded in this window.</p>'
        return html_table(
            headers=["Date", "Engineer", "Summary"],
            rows=[(r.performed_at, r.engineer, r.summary) for r in data],
        )
```

Note what the author did **not** do: no `requests.get`, no `os.environ`, no retry loop, no
`logging.getLogger` boilerplate, no HTML string concatenation of external data. All four of those
are framework concerns, and `html_table()` escapes its inputs.

### 4.4 Contexts

Contexts are frozen and therefore safe to share between worker threads.

```python
@dataclass(frozen=True, slots=True)
class RunMetadata:
    run_id: str              # uuid4 hex, generated once per job run
    started_at: datetime     # timezone-aware UTC

@dataclass(frozen=True, slots=True)
class ReportContext:
    settings: Settings       # immutable view of env-derived config
    http: HttpClient         # injected port; stub in v1
    logger: logging.Logger
    clock: Clock             # injectable for deterministic tests
    run: RunMetadata

@dataclass(frozen=True, slots=True)
class RenderContext:
    """What render() is allowed to touch. Slimmer on purpose: no HTTP, no store."""
    generated_at: datetime
    report_title: str
    logger: logging.Logger

@dataclass(frozen=True, slots=True)
class DiscoveryContext:
    settings: Settings
    http: HttpClient
    logger: logging.Logger
    clock: Clock
    run: RunMetadata
```

> **Gotcha:** `logging.Logger` is thread-safe; `Settings` and the contexts are frozen; therefore
> the shared context is safe. Anyone tempted to add a mutable cache to `ReportContext` must make it
> thread-safe and document that. The v1 answer is "don't" — use per-instance state on the *block*,
> which is single-threaded per block instance.

### 4.5 Report construction and the primary entry point

```python
@dataclass(frozen=True, slots=True)
class ReportDefinition:
    title: str
    blocks: Sequence[Block[Any]]
    subtitle: str | None = None
    metadata: Mapping[str, str] = field(default_factory=dict)  # extra header key/values

    def __post_init__(self) -> None:
        # Fail fast: an empty or duplicate-named report is a programming error.
        ...


@dataclass(frozen=True, slots=True)
class BlockOutcome:
    name: str
    status: BlockStatus        # OK | FAILED | TIMED_OUT
    duration_seconds: float
    attempts: int
    error_type: str | None = None      # exception class name, safe for display
    error_message: str | None = None   # truncated; never a traceback (§6.6)


@dataclass(frozen=True, slots=True)
class ReportRow:
    item: str
    html: str                  # inner HTML of the Data cell
    outcome: BlockOutcome
    check: str = ""            # reserved: blank in v1 (ADR-0018)


@dataclass(frozen=True, slots=True)
class Report:
    definition: ReportDefinition
    rows: tuple[ReportRow, ...]
    generated_at: datetime
    run_id: str

    @property
    def all_succeeded(self) -> bool: ...

    @property
    def failed_rows(self) -> tuple[ReportRow, ...]: ...


@dataclass(frozen=True, slots=True)
class ReportResult:
    report: Report
    html: str
    location: OutputLocation | None
```

```python
def generate_report(
    definition: ReportDefinition,
    *,
    context: ReportContext,
    writer: OutputWriter | None = None,
) -> ReportResult:
    """Collect every block (concurrently), assemble the rows, render HTML.

    With ``writer=None`` the HTML is returned but not persisted — useful when the
    caller wants to embed the document somewhere else.
    """
```

This is **the public entry point** for the common case:

```python
definition = ReportDefinition(
    title="LINE 4 — Daily Health",
    blocks=[
        MaintenanceHistoryBlock(tool_id="T-104"),
        TrendChartBlock(metric="yield", window_days=14),
        WaferMapBlock(lot_id="LOT-88213"),
    ],
)

result = generate_report(definition, context=ctx, writer=LocalDirectoryWriter("reports/"))
print(result.location.uri)          # file:///srv/app/reports/LINE-4__…__20261017T090000Z.html
print(result.report.all_succeeded)  # False if any cell holds an error
```

Lower-level pieces remain public for callers who need them (`collect_blocks`,
`render_report`) — the point of exposing them is that a caller who wants to audit *before*
writing, or render into an email body, is not forced to reimplement the pipeline.

### 4.6 Predefined reports, dynamic lists, and per-event reports

Both requirements are served by one mechanism: a `ReportDefinition` is just data, so a "predefined
report" is a function that returns one, and a "dynamic list of blocks" is a `ReportDefinition` the
caller assembled by hand.

```python
# auto_inform/reports/manufacturing.py
from auto_inform import Event, ReportContext, ReportDefinition, register_report

WAFER_FAILURE_EVENT = "WAFER_FAILURE"


@register_report(WAFER_FAILURE_EVENT)
def wafer_failure_report(event: Event, context: ReportContext) -> ReportDefinition:
    """The event supplies the context: which lot, which tool, which window."""
    lot_id = event.payload["lot_id"]
    return ReportDefinition(
        title=f"Failed wafer — {event.event_id}",
        subtitle=str(event.payload.get("summary", "")),
        metadata={"Lot": lot_id, "Tool": str(event.payload["tool_id"])},
        blocks=[
            WaferMapBlock(lot_id=lot_id),
            MaintenanceHistoryBlock(tool_id=event.payload["tool_id"]),
            TrendChartBlock(metric="yield", tool_id=event.payload["tool_id"]),
        ],
    )
```

```python
# Auto-registered by importing auto_inform.reports.manufacturing (see registry notes below)

# Somewhere else: an ad-hoc report assembled dynamically at runtime
blocks = [block_cls(**params) for block_cls, params in requested_blocks]
generate_report(ReportDefinition(title="Ad-hoc", blocks=blocks), context=ctx)
```

The registry keys on **`event_type` only**, and the factory receives the whole `Event`, so two
events of the same type can produce entirely different block sets. This is how "another event needs
a completely different context" is satisfied without a second framework mechanism.

> Convention: `ReportFactory` closes over the event and binds the event's fields into each block's
> **constructor**. The event is *not* stuffed into `ReportContext`. Explicit parameters keep blocks
> honest — a block that declares `tool_id` in its signature cannot silently depend on report-wide
> ambient state that a caller forgot to populate.

### 4.7 Events and the event store

```python
@dataclass(frozen=True, slots=True)
class Event:
    event_type: str
    event_id: str                    # stable and unique within event_type
    payload: Mapping[str, Any]       # JSON-serialisable, event-type-specific
    discovered_at: datetime          # aware UTC
    source: str                      # which discoverer/API produced it
```

`Event` is a **pure value object with no lifecycle state**. Lifecycle lives in the store, updated
through explicit calls, because a frozen record that mutates its own status is a lie:

```python
class EventStore(Protocol):
    def save(self, events: Iterable[Event]) -> SaveResult: ...
        # Upsert on (event_type, event_id). Existing rows keep their status:
        # re-discovering a processed event must NOT reset it to NEW.

    def pending(self, *, event_type: str | None = None, limit: int | None = None) -> list[Event]: ...
        # Oldest-first. Never returns PROCESSED rows.

    def mark_processed(self, event: Event, *, output_uri: str) -> None: ...
    def mark_failed(self, event: Event, *, reason: str) -> None: ...
```

Implementations:

| Class | Backend | Notes |
| --- | --- | --- |
| `SqliteEventStore(path)` | stdlib `sqlite3` | **Default.** Creates schema idempotently on first open. WAL mode. `AUTO_INFORM_SQLITE_PATH` (default `<output_dir>/events.sqlite3`). |
| `PostgresEventStore(dsn)` | `psycopg[binary]` (extra `postgres`) | Client supplies the DSN via env; framework never invents credentials. Uses `ON CONFLICT DO NOTHING` on `(event_type, event_id)`. |

Schema (identical semantics in both backends):

```sql
CREATE TABLE IF NOT EXISTS events (
    event_type   TEXT        NOT NULL,
    event_id     TEXT        NOT NULL,
    payload      TEXT        NOT NULL,   -- JSON; JSONB in Postgres
    discovered_at TIMESTAMPTZ NOT NULL,
    source       TEXT        NOT NULL,
    status       TEXT        NOT NULL,   -- NEW | PROCESSED | FAILED
    attempts     INTEGER     NOT NULL DEFAULT 0,
    last_error   TEXT,
    output_uri   TEXT,
    processed_at TIMESTAMPTZ,
    PRIMARY KEY (event_type, event_id)
);
CREATE INDEX IF NOT EXISTS events_status_type_idx ON events (status, event_type, discovered_at);
```

Store construction is explicit; there is no hidden singleton:

```python
store = SqliteEventStore.from_settings(settings)   # or PostgresEventStore(...)
```

### 4.8 Discovery

```python
class Discoverer(ABC):
    """Produces events of exactly one type from one external source."""

    event_type: ClassVar[str]

    @abstractmethod
    def discover(self, context: DiscoveryContext) -> Iterable[Event]:
        """STUB in v1: return canned events; no network."""
```

```python
@dataclass(frozen=True, slots=True)
class DiscoveryOutcome:
    discoverer: str            # class name
    event_type: str
    discovered: int
    new: int
    duplicates: int
    duration_seconds: float
    error_type: str | None = None
    error_message: str | None = None


@dataclass(frozen=True, slots=True)
class DiscoveryRun:
    run_id: str
    outcomes: tuple[DiscoveryOutcome, ...]
    started_at: datetime
    finished_at: datetime


def run_discovery(
    discoverers: Sequence[Discoverer],
    *,
    store: EventStore,
    context: DiscoveryContext,
) -> DiscoveryRun:
    """Run every discoverer; a failing discoverer is recorded, not raised.

    Discoverers run concurrently with the same timeout/retry policy as blocks.
    """
```

Note the symmetry: the collection mechanics (thread pool, timeout, retry, failure isolation) are
implemented **once** in `application/collect_blocks.py` and parameterised by a callable, so
discoverers and blocks share one implementation rather than two that drift.

### 4.9 Processing

```python
@dataclass(frozen=True, slots=True)
class EventProcessingOutcome:
    event: Event
    report_title: str
    rows: tuple[BlockOutcome, ...]
    output_uri: str | None
    error_type: str | None = None      # set when the whole event failed to process
    error_message: str | None = None


@dataclass(frozen=True, slots=True)
class ProcessingRun:
    run_id: str
    outcomes: tuple[EventProcessingOutcome, ...]
    started_at: datetime
    finished_at: datetime

    @property
    def all_succeeded(self) -> bool: ...


def run_processing(
    *,
    store: EventStore,
    context: ReportContext,
    writer: OutputWriter,
    event_type: str | None = None,     # restrict to one type; None = all registered types
    limit: int | None = None,
    fail_events_with_failed_blocks: bool = False,
) -> ProcessingRun:
    """Fetch pending events, build each event's report, write it, update the store.

    A missing ReportFactory for an event type is a ConfigurationError for that event:
    it is recorded, the event is left NEW, and the run continues with other types
    (so a half-deployed job does not consume events it cannot render).
    """
```

The processing job is the only place that advances event lifecycle. `mark_processed` is called
only after the writer has returned successfully — a report that failed to upload must not be
recorded as processed, or it is silently lost. Conversely, a report whose *blocks* failed but which
was written anyway is `PROCESSED` by default, since the error cells are the deliverable; set
`fail_events_with_failed_blocks=True` to instead mark such events `FAILED` for operator follow-up.

### 4.10 Output writers

```python
@dataclass(frozen=True, slots=True)
class OutputLocation:
    kind: str      # "file" | "s3"
    uri: str       # "file:///…" or "s3://bucket/key"


class OutputWriter(Protocol):
    def write(self, *, filename: str, content: str) -> OutputLocation: ...


class LocalDirectoryWriter:
    """Default. Creates the directory if missing; atomic write via temp file + rename."""

    def __init__(self, directory: Path | str) -> None: ...


class S3Writer:
    """Optional (extra: s3). boto3 is imported lazily so non-S3 users do not pay for it."""

    def __init__(
        self,
        bucket: str,
        prefix: str = "",
        *,
        client: Any | None = None,        # injection point for tests (moto/stubber)
        server_side_encryption: str | None = None,
        content_type: str = "text/html; charset=utf-8",
    ) -> None: ...


def build_output_writer(settings: Settings) -> OutputWriter:
    """Reads AUTO_INFORM_OUTPUT_* and returns the configured writer.

    Raises ConfigurationError if S3 is configured without a bucket, etc. Exists so a
    client job script stays 6 lines long instead of re-implementing the env plumbing.
    """
```

`OutputWriter.write` takes content as a `str`; writers encode UTF-8. Both writers are idempotent
for a given filename (overwrite), and filenames are unique per run (§6.1), so re-running a job
never destroys the previous report.

### 4.11 Registry (the internal plugin system)

Since blocks are added to this package directly and never shipped from elsewhere, the mechanism is
deliberately small — no `entry_points`, no import hooks. But the *interface* stays plugin-shaped,
so a future decision to load external packages is a one-file change (ADR-0003).

```python
# auto_inform/registry.py
BlockKey = str           # the value of Block.display_name / registry key

def register_block(cls: type[Block[Any]]) -> type[Block[Any]]:
    """Class decorator. Uses cls.display_name as the key; duplicate keys raise
    ConfigurationError (a duplicate means someone copy-pasted a block and forgot
    to rename it — better to know at import time than to get a mystery row)."""

def import_builtin_blocks() -> None:
    """pkgutil.iter_modules over auto_inform.blocks, importing every submodule.
    Idempotent; called lazily on the first registry lookup."""

def get_block(key: str) -> type[Block[Any]]: ...
def available_blocks() -> Mapping[str, type[Block[Any]]]: ...

ReportFactory = Callable[[Event, ReportContext], ReportDefinition]

def register_report(event_type: str) -> Callable[[ReportFactory], ReportFactory]:
    """Register the factory that knows how to build the report for an event type."""

def get_report_factory(event_type: str) -> ReportFactory: ...
```

Registry lookups are **lazy**, not import-time, so a caller who only ever passes explicit block
instances never pays for scanning the block package. Registration is idempotent under re-import,
which matters because `pkgutil` scans are easy to trigger twice in a long-lived process.

### 4.12 Settings and context factories

The job scripts in §7.4 and §10 are short because these five helpers live in the package. They are
the seam between "ambient environment" and "explicit injected dependencies" (ADR-0014, ADR-0017):
they read the environment exactly once, at the edge, and hand the application layer pure data.

```python
def load_settings(environ: Mapping[str, str] | None = None) -> Settings:
    """Parse and validate env vars -> frozen Settings.

    Accepts an explicit mapping so tests never touch os.environ. Raises
    ConfigurationError listing *every* invalid variable, not just the first —
    a CI job that fails four times to reveal four typos is a bad job.
    """

def configure_logging(level: str = "INFO", fmt: str = "json") -> None:
    """Install the structured handler on the root logger. Idempotent."""

def new_report_context(settings: Settings) -> ReportContext:
    """Generate a fresh run_id + started_at and wire http/logger/clock from settings."""

def new_discovery_context(settings: Settings) -> DiscoveryContext:
    """As above, for the discovery phase."""

def build_output_writer(settings: Settings) -> OutputWriter:
    """Return the writer selected by AUTO_INFORM_OUTPUT_KIND."""
```

Each returns a value rather than registering a global, so a long-lived process (a notebook, a test
session) can build several contexts with different settings without them contaminating each other.

## 5. Execution semantics

### 5.1 Concurrency, timeout and retry

One `ThreadPoolExecutor` per report (and per discovery run). Workers default to
`min(AUTO_INFORM_MAX_WORKERS, len(blocks))`.

| Setting | Meaning | Default |
| --- | --- | --- |
| `AUTO_INFORM_MAX_WORKERS` | Ceiling on in-flight blocks | `8` |
| `AUTO_INFORM_BLOCK_TIMEOUT_SECONDS` | Per-block wall-clock budget for one attempt | `60` |
| `AUTO_INFORM_BLOCK_RETRIES` | Retries **after** the first attempt | `2` |
| `AUTO_INFORM_RETRY_BASE_DELAY_SECONDS` | Backoff base: `base * 2**attempt + jitter(0..base)` | `1.0` |

Timeout accounting is deliberately explicit, because the naive implementation is wrong:

- The retry loop and the timeout check **both live inside the worker function**, so the timeout
  covers `collect()` rather than time spent queued behind other blocks.
- The calling thread reads `future.result(timeout=attempt_timeout * (attempts + 1) +
  sum(backoffs) + grace)` purely as a backstop; hitting it produces `TIMED_OUT`, not a crash.

> **Gotcha — Python cannot kill a thread.** A block that overruns is *abandoned*: the future is
> marked failed, the run continues, and the orphaned thread keeps running until its own I/O
> call returns. This is why the injected `HttpClient` **requires** a `timeout` argument on every
> call, and why `collect()` documentation says "honour the timeout". The alternative —
> `ProcessPoolExecutor` for hard kills — was rejected in ADR-0005 because it forces every block
> payload to be picklable and drags matplotlib into subprocess lifecycle management.

Retry classification is explicit rather than "retry everything", since retrying a `404` three
times is just a slower way to fail:

```python
# auto_inform/domain/errors.py
class AutoInformError(Exception): ...
class BlockError(AutoInformError): ...
class TransientBlockError(BlockError): ...      # retryable: 5xx, connection reset, "try again"
class PermanentBlockError(BlockError): ...      # not retryable: 404, bad schema, auth failure
class ConfigurationError(AutoInformError): ...  # bad env, missing factory, duplicate block name
class StoreError(AutoInformError): ...
class OutputError(AutoInformError): ...
```

Default retryable set: `TransientBlockError`, `TimeoutError`, `ConnectionError`, plus whatever the
host passes in `AUTO_INFORM_RETRYABLE_EXCEPTIONS` (comma-separated class names). **Any other
exception is treated as permanent** — including `KeyError` from a malformed API payload, which
will not improve on the second try. The framework logs the full traceback once and renders a
one-line summary into the cell.

### 5.2 Failure isolation

A block failure produces a `FAILED` or `TIMED_OUT` `BlockOutcome` and an error cell; it never
propagates. This is a hard requirement, not a policy — a report where one of twelve blocks is red
is still a useful report, and the alternative ("no output at all because the maintenance API was
briefly down") is precisely the failure mode this framework exists to prevent.

Exceptions that *are* allowed to abort a run: `ConfigurationError` during setup (bad report
definition, missing factory, unreadable settings) and `StoreError`/`OutputError` at the boundaries.
Those are operator problems, not data problems, and failing loudly is the correct behaviour.

### 5.3 Deterministic ordering

Rows appear in `ReportDefinition.blocks` order — always. Internally results land in an
`as_completed` stream and are written into a pre-sized array by index; the array is read in order at
the end. This is the whole reason the parallel map returns `list[BlockOutcome]` rather than yielding
as it finishes. A test must assert that a report containing one slow and one fast block produces
identical row order regardless of completion order.

### 5.4 matplotlib specifics

- `matplotlib.use("Agg")` is called **before** `matplotlib.pyplot` is imported, inside
  `rendering/figures.py`. There is no display in CI, and importing pyplot first is the classic
  `ImportError`/hang-in-headless-CI trap.
- matplotlib is **imported lazily** — only when a block actually calls `figure_to_data_uri()`.
  Reports made only of HTML tables therefore start fast and stay light.
- matplotlib is **not thread-safe**. A module-level `threading.Lock` in `figures.py` serialises
  figure creation and saving. Charts are the slowest thing in most reports, so this costs less than
  it sounds; the lock is held for rendering only, never across a network call.
- `plt.close(fig)` runs in a `finally` block. Without it, long-running processes accumulate figures
  until matplotlib's figure-count warning fills the log.

```python
def figure_to_data_uri(figure: matplotlib.figure.Figure, *, dpi: int = 100) -> str:
    """PNG bytes → 'data:image/png;base64,…' for direct <img src>. Thread-safe."""
```

## 6. Output HTML conventions

This section is a contract. Clients screenshot these reports, paste them into incident tickets, and
sometimes forward the raw file to people with locked-down browsers — so "self-contained" is
load-bearing.

### 6.1 File naming and location

```
<slug(title)>__<slug(event_id)>__<UTC timestamp ISO-8601 basic>.html
# e.g. LINE-4__daily-health__20261017T090000Z.html
```

- `slug()` lowercases, replaces runs of non-alphanumerics with `-`, and caps length at 60 chars to
  stay under S3 key limits and filesystem limits.
- The timestamp is UTC, `%Y%m%dT%H%M%SZ`, and makes every run's output addressable rather than
  overwriting.
- Default destination: `AUTO_INFORM_OUTPUT_DIR`, default `./reports/` relative to the process
  working directory.
- S3 keys are `f"{prefix.strip('/')}/{filename}"` when a prefix is configured.

### 6.2 Document skeleton

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>LINE 4 — Daily Health — 20261017T090000Z</title>
  <style>/* inlined; no external CSS */</style>
</head>
<body class="ai-report">
  <header class="ai-header">
    <h1 class="ai-header__title">LINE 4 — Daily Health</h1>
    <p class="ai-header__subtitle">Failed wafer — EVT-88213</p>
    <dl class="ai-header__meta">
      <dt>Run</dt><dd>9f2c1ab34de5…</dd>
      <dt>Generated</dt><dd>2026-10-17T09:00:00Z</dd>
      <dt>Lot</dt><dd>LOT-88213</dd>
    </dl>
  </header>

  <table class="ai-table">
    <colgroup>
      <col class="ai-col--item"><col class="ai-col--data"><col class="ai-col--check">
    </colgroup>
    <thead>
      <tr><th scope="col">Item</th><th scope="col">Data</th><th scope="col">Check</th></tr>
    </thead>
    <tbody>
      <!-- one <tr> per ReportRow, in definition order -->
    </tbody>
  </table>

  <footer class="ai-footer">auto_inform 0.1.0</footer>
</body>
</html>
```

### 6.3 Row markup

```html
<tr class="ai-row" data-block="maintenance-history">
  <td class="ai-cell ai-cell--item">Maintenance history — T-104</td>
  <td class="ai-cell ai-cell--data">
    <!-- block.render() output, inserted verbatim (see the trust boundary in §6.5) -->
  </td>
  <td class="ai-cell ai-cell--check"></td>
</tr>
```

The **Check** cell is emitted empty, with the class present so that a future version can add an
interactive checkbox or a status glyph without changing the document structure (ADR-0018).

### 6.4 Error cell

```html
<td class="ai-cell ai-cell--data ai-cell--error">
  <div class="ai-error" role="alert">
    <span class="ai-error__icon" aria-hidden="true">⚠</span>
    <span class="ai-error__type">TimeoutError</span>
    <span class="ai-error__message">maintenance service did not respond</span>
    <span class="ai-error__meta">3 attempts · 61.2 s</span>
  </div>
</td>
```

Rules:

- The error text is **derived from the exception type and a truncated message only**. Tracebacks go
  to the log, never into the document, because reports get emailed to people who should not be
  reading stack frames — and because stack frames leak internal hostnames and file paths.
- `AUTO_INFORM_ERROR_DETAIL=summary` (default) shows type + first line. `detailed` adds the
  exception's `__cause__` chain summary. There is no "full traceback in HTML" mode on purpose.
- Error cells are visually distinguishable but not colour-only (`⚠` glyph plus class), for
  accessibility and for black-and-white printing.

### 6.5 The trust boundary — read this before writing a block

The page shell is rendered with Jinja2 with `autoescape=True`. **Every framework interpolation is
escaped** — title, subtitle, metadata values, block names, error text.

`ReportRow.html` is inserted inside the single `|safe` filter in the codebase, in
`rendering/templates/report.html.j2`. That is the trust boundary: **`render()` returns trusted HTML
and is responsible for escaping anything it interpolates from outside the process.**

To make that the path of least resistance rather than a lecture, the framework ships escaping-first
helpers and block authors are encouraged to use them:

```python
from auto_inform import html_table, escape, figure_to_data_uri

html_table(headers=["Date", "Engineer"], rows=[(a, b)])   # escapes every cell
escape(user_supplied_string)                              # explicit escape
figure_to_data_uri(fig)                                   # no user data involved
```

A block that hand-writes f-strings around API payloads is an XSS bug waiting for a hostile string
in a vendor name. The report is only a local file, which keeps the blast radius small — but these
files are also pushed to S3 and forwarded by email, so treat payload text as untrusted.

### 6.6 Styling

- All CSS inlined in a single `<style>` element; no `<link>`, no `@import`, no web fonts.
- All classes prefixed `ai-` to survive being pasted into another page.
- Column widths via `<colgroup>`: Item 18%, Data 74%, Check 8%; `table-layout: fixed` so a wide
  chart cannot stretch the Check column off-screen.
- Images are `max-width: 100%; height: auto`. A 4000 px wafer map must not produce a 4000 px page.
- No JavaScript in v1. Sorting/filtering is explicitly deferred (§12).
- Respect `@media print` minimally: no page-breaking inside a row, header repeats on each page.

### 7.1 Environment variables

Read once at process start into a frozen `Settings` object. There is no config file and no CLI in
v1 (ADR-0014) — this is a CI job, and CI already has an environment.

| Variable | Default | Purpose |
| --- | --- | --- |
| `AUTO_INFORM_OUTPUT_KIND` | `local` | `local` or `s3` |

| `AUTO_INFORM_MAX_WORKERS` | `8` | Concurrent blocks |
| `AUTO_INFORM_BLOCK_TIMEOUT_SECONDS` | `60` | Per-attempt timeout |
| `AUTO_INFORM_BLOCK_RETRIES` | `2` | Retries after first attempt |
| `AUTO_INFORM_RETRY_BASE_DELAY_SECONDS` | `1.0` | Exponential backoff base |
| `AUTO_INFORM_RETRYABLE_EXCEPTIONS` | `""` | Extra retryable exception class names |
| `AUTO_INFORM_LOG_LEVEL` | `INFO` | Root logger level |
| `AUTO_INFORM_LOG_FORMAT` | `json` | `json` (CI) or `console` (humans) |

| `AUTO_INFORM_HTTP_BASE_URL` | — | Base URL for the injected HTTP client |
| `AUTO_INFORM_HTTP_API_TOKEN` | — | Bearer token for the injected HTTP client |

**Secrets are never logged.** `Settings.__repr__` redacts anything whose name contains
`TOKEN`, `SECRET`, `PASSWORD`, `DSN` or `KEY` — because the first debugging session in production
will `log.info("settings=%s", settings)` and that must be boring.

**AWS credentials are not our problem.** `S3Writer` uses boto3's standard credential chain (env
vars, shared config, instance profile / CI OIDC role). The framework reads no AWS keys itself.

### 7.2 v1 stubs

Per the ratified scope, every external call is a stub in v1. Blocks and discoverers are written
against the port, so swapping in a real client later is a one-line wiring change.

```python
# auto_inform/infrastructure/http_stub.py
class StubHttpClient:
    """Deterministic stand-in for the real API client.

    Fixtures are keyed by path so tests and demo reports are reproducible and
    CI needs no network. Raise StubNotConfiguredError for an unknown path —
    a loud failure beats a silently empty report.
    """

    def __init__(self, fixtures: Mapping[str, Any] | None = None) -> None: ...

    def get_json(self, path: str, *, params=None, timeout: float = 60.0) -> Any: ...

    def get_bytes(self, path: str, *, params=None, timeout: float = 60.0) -> bytes: ...
```

Also stubbed, in the same spirit: `Discoverer` subclasses in `blocks`/`reports` demo modules, and
whatever `WaferMapBlock` calls to obtain map data.

> The stub enforces the two rules that stop a real client from being a bad retrofit: **`timeout` is
> a required keyword**, and the client is **shared across threads** so it must be thread-safe.

### 7.3 Logging contract

`configure_logging(level, fmt)` sets up a JSON formatter (stdlib only — no extra dependency) with
one line per notable event. Every line carries `run_id`; every block line carries `block`,
`report_title`, `event_id` where applicable.

| Event | Fields |
| --- | --- |
| `report.start` | `run_id`, `report_title`, `block_count` |
| `block.start` | `run_id`, `block`, `attempt` |
| `block.retry` | `run_id`, `block`, `attempt`, `delay_s`, `error_type` |
| `block.finish` | `run_id`, `block`, `status`, `duration_ms`, `attempts` |
| `block.failed` | + `error_type`, `error_message`, and the traceback |
| `report.finish` | `run_id`, `report_title`, `failed_blocks`, `duration_ms`, `output_uri` |
| `discovery.finish` | `run_id`, `event_type`, `new`, `duplicates`, `duration_ms` |
| `event.processed` / `event.failed` | `run_id`, `event_type`, `event_id`, `output_uri` / `reason` |

`duration_ms` on every block is the point: when the nightly job goes from 40 s to 9 min, the log
says which block got slower, without a profiler or a reproduction.

### 7.4 Exit codes for CI

Because v1 has no CLI, the framework supplies the vocabulary and the *client job script* decides
when to exit:

```python
class ExitCode(IntEnum):
    SUCCESS              = 0   # every block OK, every event processed
    PARTIAL_FAILURE      = 1   # report produced, at least one block or event failed
    CONFIGURATION_ERROR  = 2   # bad settings, missing factory, invalid definition
    STORE_ERROR          = 3   # event store unreachable or corrupt
    OUTPUT_ERROR         = 4   # report could not be written


def exit_code_for(run: DiscoveryRun | ProcessingRun) -> ExitCode:
    """Map a finished run to a process exit code. Never raises."""
```

```python
# my_jobs/process_events.py  — the whole scheduled job
import sys

from auto_inform import (
    SqliteEventStore, build_output_writer, configure_logging,
    exit_code_for, load_settings, new_report_context, run_processing,
)

def main() -> int:
    settings = load_settings()
    configure_logging(settings.log_level, settings.log_format)
    store = SqliteEventStore.from_settings(settings)
    context = new_report_context(settings)                 # fresh run_id
    writer = build_output_writer(settings)
    run = run_processing(store=store, context=context, writer=writer)
    return exit_code_for(run)

if __name__ == "__main__":
    sys.exit(main())
```

Consequence: a report containing three failed blocks exits `1`, so the CI job goes amber/red and
somebody looks. That is intended. Operators who consider a partly-red report acceptable set
`AUTO_INFORM_FAIL_ON_BLOCK_ERROR=false` and get `0`.

## 9. Testing strategy

Not a full test plan, but the parts a developer must not skip.

| Area | Approach |
| --- | --- |
| Domain objects | Plain unit tests: duplicate block names rejected, empty report rejected, frozen semantics hold. |
| `collect_blocks` | Fake clock + fake callables. Assert: ordering preserved when the first block is slowest; one failure does not prevent others from running; retry count and backoff respected; timeout yields `TIMED_OUT` without aborting the run. |
| Runners | `FakeEventStore` in `conftest.py` (in-memory dict, same semantics as the SQL schema). Assert re-discovery does not reset `PROCESSED`; a failed write leaves the event `NEW`; a missing factory skips rather than consumes. |
| Stores | Integration tests against a temp SQLite file. Postgres tests marked `@pytest.mark.postgres` and skipped unless `AUTO_INFORM_TEST_POSTGRES_DSN` is set — CI without a Postgres service must stay green. |
| Writers | Local writer: temp dir, atomic rename, filename slug rules (including a title with `/`, emoji and 300 chars). S3 writer: injected stub client, assert key composition and content type. No live AWS. |
| Rendering | Golden-file tests for the full document with a two-block fixture report. Normalise insignificant whitespace before comparing. This is the output contract from §6 made executable. |
| Figures | Smoke test only: build a figure, get a URI starting `data:image/png;base64,`, and assert no figures are left open afterwards. Do not assert on pixels. |
| Thread safety | A test that constructs 16 blocks in parallel, half of which render figures, asserting no exception and stable row order. This is the test that catches a missing figure lock. |

Test naming (house style, JUnit-style form):

```python
def collect_blocks_with_one_failing_block_should_isolate_failure_and_preserve_order() -> None: ...
def event_store_save_with_already_processed_event_should_not_reset_status() -> None: ...
def slug_title_with_path_separators_should_replace_with_hyphens() -> None: ...
```

Every test body is split into `# given / # when / # then` comments.

**CI expectation:** GitHub Actions running `ruff`, `mypy --strict`, and `pytest` with the Postgres
service absent (that suite self-skips). Note that the owner did not select CI setup as a v1
requirement — it is recommended rather than mandated; see §12.

## 10. Worked end-to-end example

Three files, which together are the whole "how do I use this" story.

**1. A block that is entirely local (no API):**

```python
# auto_inform/blocks/wafer_map.py
import matplotlib.pyplot as plt
import numpy as np

from auto_inform import Block, ReportContext, RenderContext, figure_to_data_uri


class WaferMapBlock(Block[np.ndarray]):
    display_name = "Wafer map"

    def __init__(self, *, lot_id: str, name: str | None = None) -> None:
        super().__init__(name=name or f"Wafer map — {lot_id}")
        self._lot_id = lot_id

    def collect(self, context: ReportContext) -> np.ndarray:
        # STUB: real implementation fetches the bin map for this lot.
        return np.random.default_rng(0).random((25, 25))  # noqa: NPY002

    def render(self, data: np.ndarray, context: RenderContext) -> str:
        fig, ax = plt.subplots(figsize=(4, 3), dpi=100)
        try:
            ax.imshow(data, cmap="RdYlGn", interpolation="nearest")
            ax.set_title(f"{self._lot_id} bin map")
            fig.tight_layout()
            return f'<img class="ai-figure" src="{figure_to_data_uri(fig)}" alt="Wafer bin map for {self._lot_id}">'
        finally:
            plt.close(fig)
```

> Note the `alt` text is built from `self._lot_id`, a constructor parameter, not from API payload —
> and if it were from payload it would need `escape()`. The `alt` attribute is inside a
> hand-written f-string, which is exactly the place people forget.

**2. A discovery job:**

```python
# my_jobs/discover_wafers.py

from auto_inform import (
    Event, DiscoveryContext, Discoverer, SqliteEventStore,
    configure_logging, exit_code_for, load_settings, new_discovery_context, run_discovery,
)

class FailingWaferDiscoverer(Discoverer):
    event_type = "WAFER_FAILURE"

    def discover(self, context: DiscoveryContext):
        # STUB: real implementation queries the yield API.
        for lot_id in context.http.get_json("/yield/failures", timeout=30.0)["lots"]:
            yield Event(
                event_type=self.event_type,
                event_id=f"WAFER_FAILURE:{lot_id}",
                payload={"lot_id": lot_id, "tool_id": "T-104", "summary": "Below yield threshold"},
                discovered_at=context.clock.now(),
                source="yield-api",
            )

def main() -> int:
    settings = load_settings()
    configure_logging(settings.log_level, settings.log_format)
    store = SqliteEventStore.from_settings(settings)
    run = run_discovery(
        [FailingWaferDiscoverer()],
        store=store,
        context=new_discovery_context(settings),
    )
    return exit_code_for(run)

if __name__ == "__main__":
    sys.exit(main())
```

## 11. Decision log

Format: context → decision → consequences. Each of these was a fork where the alternative was
genuinely defensible; recording *why* is what stops a future contributor from "fixing" it.

**ADR-0001 — Library-first; no CLI in v1.**
*Context:* CI needs meaningful exit codes, which usually implies a `main()`. *Decision:* the
library exposes `ExitCode` and `exit_code_for()`, and the client's own job script (≈15 lines) does
`sys.exit()`. *Consequences:* the public surface stays small and every code path goes through the
tested API; each consuming team writes a small script, which is acceptable at this scale. Revisit
if the number of job scripts exceeds ~5 and they start drifting.

**ADR-0002 — Blocks split into `collect()` and `render()`.**
*Context:* A single `build_html()` method would be simpler to write. *Decision:* split them,
because rendering is pure and therefore testable with no network, no clock, and no fixtures.
*Consequences:* two methods per block; `DataT` is opaque to the framework. In exchange, HTML
generation bugs are caught by fast unit tests instead of in a scheduled job at 3 a.m.

**ADR-0003 — Internal registry with a package scan, not `entry_points`.**
*Context:* "plugin system" could mean external distributions, but this is an internal tool where
blocks are added directly to the package. *Decision:* `@register_block` + `pkgutil` scan of
`auto_inform.blocks`, with lookups that are lazy and idempotent. *Consequences:* zero packaging
ceremony to add a block — create a module, decorate a class, done. The `Block` interface is still
the plugin interface, so moving to `entry_points` later changes only `registry.py`.

**ADR-0004 — A failing block renders an error cell; it never aborts the report.**
*Context:* partial data vs. no data. *Decision:* isolate, don't abort; operators who want strictness
get it via exit code (`AUTO_INFORM_FAIL_ON_BLOCK_ERROR`), not by losing the artefact.
*Consequences:* reports are always produced, so a broken block is silently red until someone reads
the log — mitigated by structured `block.failed` lines and a non-zero exit code.

**ADR-0005 — Threads with cooperative timeouts; not processes, not asyncio.**
*Context:* Blocks are synchronous and API-bound, so parallelism is required, and a runaway block
must not hang the job. *Decision:* `ThreadPoolExecutor`; the timeout is enforced inside the worker,
with an outer backstop. *Consequences:* a timed-out block's thread is abandoned, not killed — so
every HTTP call must carry a client-side timeout (enforced by the `HttpClient` signature). Rejected
`ProcessPoolExecutor` because payloads would need to be picklable and matplotlib lifecycle in
subprocesses is genuinely awful; rejected asyncio because it would force every block author to
write async code and to get cancellation semantics right.

**ADR-0006 — Generic event envelope with an opaque JSON payload; not typed subclasses.**
*Context:* New event types arrive constantly, and the store must handle types it has never heard
of. *Decision:* `Event(event_type, event_id, payload, discovered_at, source)`. *Consequences:*
adding an event type requires no migration and no framework change; the cost is that payload shape
is validated by each `ReportFactory`, not by the framework. That validation must therefore be
explicit and is the factory's responsibility.

**ADR-0007 — `EventStore` port with SQLite default and optional Postgres.**
*Context:* Two independently scheduled jobs must communicate, and production already has Postgres.
*Decision:* define the port once; SQLite is the zero-configuration default so the framework is
usable in a dev container, Postgres is an extra requiring a client-supplied DSN.
*Consequences:* two implementations to keep honest — mitigated by integration tests that run the
same shared-behaviour suite against both, and by an identical schema.

**ADR-0008 — Discovery and processing are separate, store-mediated jobs.**
*Context:* The naive design has one job discover events and immediately generate reports, which
makes a slow report block throttle discovery. *Decision:* decouple via the store; the registry maps
`event_type` → `ReportFactory`, and the factory receives the whole `Event`. *Consequences:* either
phase can be re-run, throttled or failed independently, and retries are natural (an event stays
`NEW` until it is successfully processed). The cost is a stateful component in a previously
stateless library, which is why the port and the default implementation arrived in the same
decision.

**ADR-0009 — matplotlib with the Agg backend, PNG → base64 data URI; no JS chart library.**
*Context:* Interactive charts (Plotly/Chart.js) versus static images. *Decision:* static images via
matplotlib, lazily imported and serialised behind a module lock. *Consequences:* fully
self-contained, printable, email-safe documents, and one charting API for authors to learn. Costs:
larger files, no hover/zoom, and a heavy dependency — accepted, with lazy import keeping pure-HTML
reports fast.

**ADR-0010 — Jinja2 for the page shell, escaped by default.**
*Context:* f-strings versus a template engine. *Decision:* one Jinja2 template for the document,
`autoescape=True`, loaded via `importlib.resources`. *Consequences:* one obvious place where HTML
is produced, and a single auditable `|safe` in the entire codebase (§6.5). Blocks still return raw
strings — a per-block template was rejected as ceremony that most blocks don't need.

**ADR-0011 — One block, one row.**
*Context:* A block could reasonably expand into N rows, or a factory could produce one instance per
row. *Decision:* one block produces exactly one row in v1. *Consequences:* the row contract stays
trivially simple and failures map one-to-one to cells. Blocks that need multiple rows emit an inner
`<table>` or list inside their single cell — which is visually acceptable and avoids a second
lifecycle concept. Revisit if authors start producing 40-row inner tables.

**ADR-0012 — `ReportRow.html` is a trust boundary; the framework escapes its own output only.**
*Context:* Blocks return HTML strings by owner decision. *Decision:* the framework escapes
everything it interpolates; block output is inserted with `|safe` and block authors are given
escaping-first helpers. *Consequences:* maximum authoring freedom, and a documented XSS surface
that authors must handle. Acceptable because reports are internal artefacts, but not because it
can't hurt — S3-hosted and forwarded files are readable by people outside the team.

**ADR-0013 — Structured (JSON) logging with per-block timing.**
*Context:* A nightly CI job that silently degrades is hard to diagnose. *Decision:* stdlib
`logging` with a JSON formatter; every block logs start/finish/failure with `duration_ms`.
*Consequences:* no new dependency, and "which block slowed down" is answerable from the log alone.
Rejected third-party structured-logging libraries to keep the dependency budget on matplotlib
instead.

**ADR-0014 — Configuration via environment variables only.**
*Context:* Config file, settings object, or env. *Decision:* env only, parsed once into a frozen
`Settings`, with redaction in `__repr__`. *Consequences:* matches CI and container conventions and
avoids a config-file format nobody asked for. Tests construct `Settings` directly, bypassing the
environment entirely.

**ADR-0015 — Installed from git, not published to PyPI.**
*Context:* Internal tool. *Decision:* `pip install "auto_inform @ git+…"`, extras for optional
backends. *Consequences:* no release process to maintain; CI must pin a tag or SHA, because pip
caches git installs and an unpinned `@main` will eventually serve you a stale package at the worst
possible moment.

**ADR-0016 — Report definitions are Python, not declarative config.**
*Context:* YAML report definitions would let non-developers author reports. *Decision:* Python
factories returning `ReportDefinition`. *Consequences:* full expressiveness — per-event logic,
computed parameters, reuse — with no schema to maintain. The cost is that report authoring requires
Python, which is fine for an internal tool whose authors are the same people who write the blocks.

**ADR-0017 — Blocks receive an injected context; they never build clients or read the environment.**
*Context:* `requests.get(os.environ["TOKEN"])` in a block is the fastest way to write it.
*Decision:* `ReportContext` carries settings, an HTTP client, a logger and a clock; injected at the
edge. *Consequences:* blocks are testable with a fake context and cannot leak credentials into logs
casually. Shared across threads, therefore frozen — see the gotcha in §4.4.

**ADR-0018 — The Check column is emitted empty in v1.**
*Context:* The column exists for human pass/fail sign-off that happens *after* the file is
produced. *Decision:* emit `<td class="ai-cell ai-cell--check"></td>`, reserving the class and
column so a later version can add interactive controls without a document-structure change.
*Consequences:* the file is a static artefact in v1; where human input would be *stored* is an open
question (§12), and pretending otherwise would be a design fiction.

## 12. Open questions

Owned by the product owner; each has a default so implementation is not blocked.

| # | Question | v1 default |
| --- | --- | --- |
| 1 | Does the event store need claim/lease semantics for concurrently running processing jobs (multiple CI workers)? | No. Single-writer assumed; `pending()` + `mark_*` are not atomic across processes. Documented as a limitation. |
| 2 | Where would human Check-column sign-off be persisted? | Not in v1. Future candidates: a sidecar store keyed by `(run_id, block)`, or a small service. |
| 3 | Retention/pruning of the events table? | Nothing automatic; a `prune(before=...)` helper is a candidate for v0.2. |
| 4 | Should a run manifest (JSON with per-block outcomes and URIs) be written alongside the HTML? | Not in v1 — the structured log covers it. Cheap to add later since `Report` already carries the data. |
| 5 | GitHub Actions CI with ruff/mypy/pytest? | Recommended, not mandated. The test suite is written so it passes without a Postgres service. |
| 6 | Interactive sorting/filtering and a "show only failures" toggle in the HTML? | No JS in v1. The document is a report, not a dashboard. |
| 7 | Is one report per file final, or will several reports need to share a page? | One report per file in v1. |
| 8 | S3 object lifecycle, signed URLs, or public-read for browser viewing? | None automated; consumers use presigned URLs out of band. |
| 9 | Do blocks ever need to run in a fixed order because one primes a cache another uses? | No — insertion order is a *display* guarantee, not a dependency mechanism. If needed, a factory can pre-fetch and inject the shared data (ADR-0002). |
| 10 | Localisation / RTL support? | Out of scope; English, LTR, UTC timestamps. |

## 14. Appendix — suggested implementation order

Each step is independently reviewable and leaves the repository green.

1. Packaging skeleton, `src/` layout, `pyproject.toml`, dev extras, ruff/mypy config.
2. `domain/` — `Block`, `Event`, `Report`, `ReportRow`, `BlockOutcome`, error hierarchy, `ExitCode`.
3. `rendering/` — Jinja2 shell, cells, error cell, escaping helpers, `figure_to_data_uri()`, golden
   tests. *(Do this before the pipeline: it fixes the output contract that everything else targets,
   and it is the part most likely to change shape if left late.)*
4. `registry.py` + `blocks/` scan + the first two built-in blocks (`maintenance_history`,
   `wafer_map`) against the stub HTTP client.
5. `application/collect_blocks.py` — concurrency, timeout, retry, ordering. *(The highest-risk
   module; it deserves its own review and its own test file.)*
6. `generate_report()` + `LocalDirectoryWriter` + `render_report()` — the public entry point now
   works end to end.
7. `infrastructure/settings.py` + `logging_setup.py` + `http_stub.py`.
8. `stores/sqlite_store.py` and `run_discovery`; then `run_processing` + `exit_code_for()`.
9. `reports/manufacturing.py` and the two example job scripts; README with the install gotchas.
10. `stores/postgres_store.py`, `writers/s3_writer.py`, and the shared store-behaviour test suite.
